# 3D map audit and zoom-flicker remediation — October 22, 2026

The audit found four runtime bugs and two verification defects. Each runtime
change has its own commit and regression evidence. The Rainier-centered,
fixed-angle zoom regression passes with both raster LOD settings after the
renderer correction. Live Rainier elevation and the exact originally observed
flash are not established by these synthetic fixtures. One strict, non-visible
tile-warming timing criterion remains open; this is not universal flicker closure.

## Scope and evidence

Reviewed the terrain frame's construction, source/layer ordering, route and
peak validation, camera events, markers, vector/raster swaps, error policy,
settings boundary, warming, suspension and resume; the isolated bridge's
activation and frame generations; coordinator/camera/compass helpers;
DEM cache ownership, cancellation and bounded tile planning; the terrain overlay
adapter and native map handoffs; and the shipped MapLibre source and build path.

## Findings and focused commits

| ID | Priority | Finding and repair | Commit |
| --- | --- | --- | --- |
| T1 | P1 | MapLibre 6.13.0's `TileManager.update` uses the source's configured LOD callback for DEM downloads, while `TerrainTileManager.update` omits that callback when choosing the render-to-texture grid. Those grids can disagree, leaving terrain on coarse ancestors even after all requested tiles settle. The build now applies a guarded, one-line callback correction. Version/shape changes fail the build for review; worker/shared files remain byte-identical npm artifacts. | `c73be873` |
| T2 | P2 | Warming only checked movement between downloads and had no transport cancellation or suspended-state guard. A gesture or hidden frame could keep speculative requests alive and hidden `moveend` events could restart them. Warming now has an abort owner, cancels on movement/suspend/teardown, and ignores hidden camera activity. | `6dbde347` |
| T3 | P2 | `createFrame` awaited activation/settings without retaining the launch identity. Cancel could run before the iframe existed, then the delayed reply could mount the abandoned renderer. A launch revision now retires starts on destroy, failure and feature disable. | `1b0e6902` |
| T4 | P2 | Zooming below the peak cutoff cleared markers without retiring their request id. A delayed reply could restore those dots, including during the debounce window. The cutoff now invalidates requests, rejects below-cutoff replies and clears markers even during provider cooldown. | `07095e77` |
| T5 | P2 | The LOD verifier depended on `painter.maybeDrawCoords`, removed from MapLibre 6.13. The replacement paints desired/actual DEM provenance through the custom terrain hook and reads the actual framebuffer. Tile metadata and pixels are sampled in the same rendered frame. It also rejects unknown selections and executes exactly 20 fixed-angle zoom cases. | `652e23b6` |
| T6 | P3 | Firefox's terrain verifier checked Sentinel, which already expanded its details, then blindly clicked the disclosure and collapsed the capture picker. It now checks `aria-expanded` before opening the section. | `16480973` |

The runtime regressions for T2–T4 were run against the unfixed code and failed
on the affected behavior: uncancelled transport, an abandoned iframe mounting,
and stale dots reappearing. T1's regression executes the actual distributed
terrain update method; its callback assertion fails on the unpatched module.
The patch and its constraints live in
[maplibre-terrain-lod-patch.mjs](../../scripts/maplibre-terrain-lod-patch.mjs),
with [shipped-method coverage](../../test/project/maplibre-terrain-lod-patch.test.mjs).
Build documentation and AMO reviewer metadata disclose the modified main module.

## Rainier zoom reproduction

The repaired [LOD verifier](../../scripts/verify-terrain-lod.mjs) centers the
camera on `[-121.760395, 46.851731]`, with a 1098 × 698 CSS-pixel terrain frame
in a 1240 × 1020 host. It uses a continuous, synthetic Terrarium range encoded
as lossless WebP, delayed by 140 ms per tile after encoding. Drape images are
also local fixtures, while the real bundled MapLibre, worker and terrain
runtime render on the hardware GPU.

At each pitch, 60° and 75°, zoom follows:

`14 → 14.25 → 14.8 → 15.2 → 14.8 → 14.2 → 13.8 → 13.2 → 12.8 → 13.2 → 14`.

Both the fixed and negative-control runs used the same fixture, warming/tilt
sequence, 12-second settle deadline, camera assertions and provenance probe.
Only the served renderer module differed: the negative control used the
unmodified npm main module, without resetting the checkout.

- **Unpatched:** five settled zoom views at pitch 75° retained a DEM deficit.
  At zoom 15.2, 44,874 of 48,106 sampled surface pixels (about 93%) remained one
  level too coarse. The full run reported ten acceptance failures across tilt,
  reversal and fixed-angle zoom. This was a measured surface defect, not a
  missing API or fixture setup timeout.
- **Patched:** all 20 fixed-angle zoom cases passed for `L_OS`, and all 20
  passed for `L_OT`; no visible DEM shortfall was recorded in those zoom sweeps.
  The OpenTopoMap specification also passed all four tilt criteria. The
  full-detail drape retained the timing gap described below.

These measurements support the LOD mismatch as a zoom-detail flicker cause.
They do not prove that every possible blank frame, imagery-level transition,
network stall or live Rainier flash has the same cause.

- T5–T6: both terrain verification defects repaired; the obsolete framebuffer
  call and hidden-picker action no longer prevent the relevant checks.
- `npm test`: **3,196 passed, 0 failed** on the final runtime and probe changes.
- `npm run lint`: passed; eight existing, reviewed web-ext warning instances
  remain within their owned allowances.
- Project/build/release/documentation checks for the vendor correction:
  **83 passed**. Focused provenance/showcase/readiness/documentation checks:
  **20 passed**.
- Real unpacked-extension verification passed in hidden Chrome for Testing
  **156.0.8078.4** and installed Firefox **158.0.1**, at **1000 × 760**.
- The real-extension Chrome map-layer verifier passed on **Apple M3 Pro
  ANGLE/Metal**, hidden at **1000 × 700**, including raster pixels, partial
  recovery, zoom feedback, basemap changes and suspend/resume.
- Focused terrain verification passed in hidden Playwright Firefox **157.0**
  on **Apple M3 Pro ANGLE/Metal**, with a **1000 × 760** host: scroll zoom,
  right-drag/Ctrl-drag, bearing, resized **748 × 448** canvas, peak popups,
  compasses and Sentinel suspend/resume. Its light/dark and 375/1000-pixel
  warning-geometry cases also passed.
- The actual terrain image, without the diagnostic provenance colors, was
  visually inspected in hidden Chrome at **1098 × 432** and **388 × 432**,
  light and dark. Controls, attribution and basemap selection remained visible.
  These used synthetic elevation/imagery at Rainier coordinates.
- Minified release build and a disposable Chrome ZIP passed archive validation
  (**108 entries**). This is a local package check, not store submission or a
  packaged-browser execution claim.
- Owned browser/server process checks found no remaining audit processes.
  Local logs, renders and the candidate ZIP are intentionally retained under
  `web-ext-artifacts/3d-map-audit-2026-10-22/`; disposable scripts, profiles and
  certificates are not retained.

### Intentionally not changed

- No extra provider prefetch, higher warming budget, or broader host permission.
  Speculative work retains the 32-tile cap, two consumers and idle scheduling.
- Shared cache subscriptions still preserve a renderer download when only its
  speculative consumer cancels. Raw GPX, route payload and feature-consent
  boundaries remain unchanged.
- MapLibre's ground-following camera default remains. The repair aligns its
  two terrain grids instead of disabling terrain collision or moving the camera
  to hide a rendering error.
- Ordinary changes of imagery detail are not hidden with a full-map overlay,
  animation, deferred input or layout reflow.

### Changed but not fully proven

- **Strict full-detail tilt timing:** `L_OS` still returned a nonzero exit for
  one criterion: the 67° → 70° step had a four-level fallback on 8% of terrain
  tiles for **140 ms**, against the unchanged **120 ms** budget. The probe
  recorded **no visible pixel shortfall** during that step. This conservative
  tile-level performance gate remains open; it was not loosened or called green.
- **Live Rainier:** no live Mapterhorn/OpenTopoMap Rainier dataset or exact
  original browser gesture was used. Synthetic Rainier-centered coverage and
  hardware rendering are established; live provider behavior remains a release
  spot-check.
- **Other broad checks:** the existing Chrome terrain visual script stopped at
  its pre-existing native-2D toggle gap assertion (**41 px** versus **40 px**,
  **1000 × 900**), before 3D. The broader Firefox snow-map suite stopped while
  waiting for its station-catalog activation state, before reaching terrain.
  The independent hardware checks above passed, but do not erase those failures.
- **Native evidence:** headless/protocol output does not establish physical
  focus, window placement, native menus, permission prompts or screen-reader
  behavior. No visible browser was raised over the user's work.
- No hosted CI, browser-store submission or published release was performed.
