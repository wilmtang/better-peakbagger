# UX audit — October 22, 2026

Starting tree: clean `main` at `c121027f`, version 4.0.2. This audit applies
ui-ux-pro-max to the existing extension design. Implementation is authorized.
It is a bounded review of every product surface, not a claim that every possible
interaction, assistive technology or live service has been proven.

## Findings before implementation

| ID | Priority | Finding | Owning source / acceptance |
| --- | --- | --- | --- |
| U1 | P2 | Capture progress replaces its Cancel control on every poll. Opening/deleting drafts natively disables the active button and loses keyboard focus. | `popup/popup.js`: preserve progress action identity, focus through pending/error/retry, and block duplicate requests. |
| U2 | P2 | Permission-page actions drop focus during the prompt and after denial/error. | `src/ui/map-access.js`: all four providers; retain focus while pending, guard repeated activation, deliberately move to Close after success. |
| U3 | P2 | Send GPX actions drop focus while preparing a transfer and do not recover it after failure. | `src/ascent/ascent-gaia.js`: all four providers, permission/preparation/error/success, duplicate prevention and unchanged geometry. |
| U4 | P2 | Settings backup/key actions natively disable focused controls. Ignored-climber completion unconditionally returns focus, even after the reader moves elsewhere. Reorder grips also lose focus while saving. | `options/`: inspect and exercise async action owners; preserve focus, honor deliberate focus movement, preserve review-before-restore. |
| U5 | P2 | Photo-library backup disables its active button while the request is pending. | `photos/photos.js`: retain focus and prevent duplicate backup requests in library and Settings. |

U1–U3 were observed with shipped assets in isolated HTTPS Peakbagger fixtures,
hidden Chrome 156.0.8078.4 and Playwright Firefox 157.0 at 390 × 900. The existing
geometry assertions pass while focus becomes BODY. U4/U5 are source-confirmed
candidates until their regression probes establish browser behavior. No runtime
files had been changed when these findings were reported.

## Surface inventory and review boundaries

- Capture popup: startup/recovery, progress/cancel, selection, timestamps,
  opening drafts and deleting captured data.
- Settings: navigation, units, feature gates, map/filter order, credentials,
  GitHub connection, settings/favorites/ignored/photos backup and restore.
- Standalone drafts and climber lists: filtering, row replacement, copy,
  confirmation, undo and pagination.
- Photo Topos and guide: editing/selection/route points, import/upload, library,
  backup, contextual tools, toast and navigation.
- Ascent editor: GPX import, prepared drafts, report modes, recovery, photo
  preparation and native Save boundaries.
- Saved ascent and profile: backup/check/retry, bulk preparation/progress,
  pause/cancel and GPX handoffs.
- Peak/ascent data: filters, climber cards, weather/model/day/hourly/source,
  snow, Sun & Moon, GPX chart and map controls/overlays/terrain.
- Gaia, onX, AllTrails and CalTopo access pages.

Review includes current source, recent closure ledgers, the integrated layout
matrix and real-extension smoke coverage. The matrix uses controlled service
responses; some photo cases inspect presentation without the editor runtime.
Changed interactions require additional real runtime probes. Existing audit
records are evidence of prior work, not substitutes for current verification.

### Intentionally not changed

  boundaries. No additional preferences, remote assets or dependencies.

OS focus/window placement and screen-reader announcements require native/live
checks. Hidden DOM focus and screenshots cannot establish those behaviors.
