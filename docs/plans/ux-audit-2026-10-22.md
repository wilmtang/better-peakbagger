# UX audit — October 22, 2026

Starting tree: clean `main` at `c121027f`, version 4.0.2. This audit applies
ui-ux-pro-max to the existing extension design. Implementation is authorized.
It is a bounded review of every product surface, not a claim that every possible
interaction, assistive technology or live service has been proven.

## Findings before implementation

| ID | Priority | Finding | Owning source / acceptance |
| --- | --- | --- | --- |
| U1 | P2 | Capture progress replaces its Cancel control on every poll. Opening/deleting drafts natively disables the active button and loses keyboard focus. | `popup/popup.js`: preserve progress action identity, focus through pending/error/retry, and block duplicate requests. |
| U2 | P2 | Permission-page actions drop focus during the prompt and after denial/error. | `src/ui/map-access.js`: all four providers; retain focus while pending, guard repeated activation, deliberately move to Close after success. |
| U3 | P2 | Send GPX actions drop focus while preparing a transfer and do not recover it after failure. | `src/ascent/ascent-gaia.js`: all four providers, permission/preparation/error/success, duplicate prevention and unchanged geometry. |
| U4 | P2 | Settings backup/key actions natively disable focused controls. Ignored-climber completion unconditionally returns focus, even after the reader moves elsewhere. Reorder grips also lose focus while saving. | `options/`: inspect and exercise async action owners; preserve focus, honor deliberate focus movement, preserve review-before-restore. |
| U7 | P2 | Summit choices remain editable while the opening request has already frozen the submitted selection; Delete looks available while busy. Failed deletion can restore an older selection. | `popup/popup.js`: lock choices immediately, expose action availability and retain current selection through recovery. |
| U6 | P3 | Scrolled credential text bleeds through the sticky Photo Topos header and competes with its title. | `photos/photos.css`: use the existing opaque background; inspect scrolled light/dark narrow states. |
| U5 | P2 | Photo-library backup disables its active button while the request is pending. | `photos/photos.js`: retain focus and prevent duplicate backup requests in library and Settings. |

U1–U3 were observed with shipped assets in isolated HTTPS Peakbagger fixtures,
hidden Chrome 156.0.8078.4 and Playwright Firefox 157.0 at 390 × 900. The existing
geometry assertions pass while focus becomes BODY. U4/U5 are source-confirmed
candidates until their regression probes establish browser behavior. No runtime
files had been changed when these findings were reported.

## Surface inventory and review boundaries

- Capture popup: startup/recovery, progress/cancel, selection, timestamps,
  opening drafts and deleting captured data.
- Settings: navigation, units, feature gates, map/filter order, credentials,
  GitHub connection, settings/favorites/ignored/photos backup and restore.
- Standalone drafts and climber lists: filtering, row replacement, copy,
  confirmation, undo and pagination.
- Photo Topos and guide: editing/selection/route points, import/upload, library,
  backup, contextual tools, toast and navigation.
- Ascent editor: GPX import, prepared drafts, report modes, recovery, photo
  preparation and native Save boundaries.
- Saved ascent and profile: backup/check/retry, bulk preparation/progress,
  pause/cancel and GPX handoffs.
- Peak/ascent data: filters, climber cards, weather/model/day/hourly/source,
  snow, Sun & Moon, GPX chart and map controls/overlays/terrain.
- Gaia, onX, AllTrails and CalTopo access pages.

Review includes current source, recent closure ledgers, the integrated layout
matrix and real-extension smoke coverage. The matrix uses controlled service
responses; some photo cases inspect presentation without the editor runtime.
Changed interactions require additional real runtime probes. Existing audit
records are evidence of prior work, not substitutes for current verification.

## Closure ledger

### Fixed and verified

- U1: capture progress retains the Cancel node and reserves actual progress
  copy; busy open/delete/cancel actions keep focus and reject duplicate work.
  Completion moves focus only when the old surface owned it. Two new unit
  assertions failed on the original code. All 50 popup tests pass after build;
  eight hidden Chrome/Firefox light/dark 390/1280 × 900 cases pass, including
  progress phase changes, cancellation, opening failure/retry and deletion
  failure. Focused ESLint and diff checks pass; rendered light/dark screenshots
  were inspected. Native popup chrome and OS focus remain outside this proof.

- U2/U3: all four map permission/transfer flows preserve the active button
  through pending/error/retry and reject duplicate Enter/Space activation.
  Granted access moves to Close only when the initiating control owns focus;
  completed transfers respect focus moved to native content. The new Firefox
  assertions failed on the original pending focus in both flows. All 18 focused
  unit tests and 16 browser variants pass (Chrome/Firefox, light/dark,
  390/1280 × 900); each variant exercises all four providers. Light/dark narrow
  screenshots were inspected. Focused ESLint and diff checks pass.

- U4: Settings backup, restore, confirmation, key and My Ascents actions keep
  keyboard focus while pending and guard repeat activation. Late previews and
  completion respect focus moved elsewhere; removing the key continues at Save.
  Reorder grips and provider checkboxes remain focusable while saves settle.
  The original browser probe reproduced focus loss and Space scrolling in nine
  actions plus focus reclamation in photo/ignored restore. All 204 options tests,
  eight expanded Settings-action browser variants and eight existing Settings
  variants pass. Each expanded variant covers ten actions at normal/doubled
  control text plus four restore-confirmation error/retry/success paths. The
  existing Settings matrix checks reorder pending focus and geometry. Browsers
  are hidden Chrome 156.0.8078.4/Firefox 157.0, light/dark, 390/1280 × 900.
  Narrow dark enlarged controls and desktop light layouts were visually checked;
  focused ESLint and diff checks pass. Text scaling is not native browser zoom.

- U5: photo-library backup stays focusable through the write and status refresh,
  rejects duplicate requests, and preserves Search focus when the user moves
  there. Connection failure and IndexedDB reload still disable unavailable work.
  The new hidden Firefox assertion fails on the original pending focus. All
  291 photo tests and eight Chrome/Firefox light/dark 390/1280 × 900 runtime
  variants pass, including normal/doubled control text, error/retry/success,
  panel/heading/following-content geometry and scroll. The real packaged Chrome
  library passes nine status states across six widths plus 304 backup-status
  checks at 1440/390/320/780 × 1100 and CSS zoom 1/2, using Apple M3 Pro Metal.
  The narrow dark pending screenshot was inspected; focused ESLint passes.

- U6: the sticky Photo Topos header uses the existing opaque theme background.
  Scrolled narrow dark and light screenshots were inspected; text no longer
  competes with the title. All eight photo-backup browser variants still pass.
  This visual defect was observed before the CSS change; no automated pixel
  regression is claimed.

- U7: capture selection and timestamp choices lock immediately during opening
  and deletion; sibling actions show their unavailability. Failure releases
  choices and retains the current summit selection. New unit and hidden Chrome
  assertions failed on the original editable state. All 51 popup tests and
  eight Chrome/Firefox light/dark 390/1280 × 900 focus/layout variants pass;
  the narrow dark result/error rendering was inspected. Focused ESLint and
  diff checks pass.

### Intentionally not changed

- Existing palette, type, component language, native Save and consent/privacy
  boundaries. No additional preferences, remote assets or dependencies.
- Deliberate result/disclosure expansion and navigation to requested tabs.
- The separate upstream dependency advisory and proposed product features in
  the other active plans are outside this UX implementation.

### Changed but not fully proven

No runtime changes yet. Live provider writes, real browser permission prompts,
OS focus/window placement and screen-reader announcements require native/live
checks. Hidden DOM focus and screenshots cannot establish those behaviors.

## Verification record

The initial integrated layout run and focused keyboard reproductions are in
progress. Regression assertions must fail for the visible defect on the audited
code before passing on the fix when practical. Final evidence records browser,
viewport, theme, enlarged layout/text coverage and teardown.
